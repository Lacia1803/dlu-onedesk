# Tickets System Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the full lifecycle of support tickets: creation, assignment, status tracking, and commenting.

**Architecture:** Use Server Actions for all mutations (creating/updating tickets, adding comments). The UI will rely on Server Components for fetching and Client Components for forms and interactivity.

**Tech Stack:** Next.js 14, Prisma, PostgreSQL, Zod, React Hook Form, Tailwind CSS, Shadcn UI.

**Spec:** `specs/04-tickets.md`

## Global Constraints

- Strict TypeScript.
- Server Components by default.
- Users can only see/interact with their own tickets; Technicians/Admins see all tickets.
- All backend functions must authorize the caller based on their role and ID.

### Task 2: Server Actions

**Files:**

- Create: `src/app/actions/ticket-actions.ts`

**Interfaces:**

- Consumes: Zod schemas, DB context.
- Produces: `createTicket`, `updateTicket`, `addTicketComment`.

- [ ] **Step 1: Write Create & Comment Actions**
      Create `src/app/actions/ticket-actions.ts` (`"use server"`).
- `createTicket(data)`: Validate with `ticketSchema`, set `creatorId` to `session.user.id`.
- `addTicketComment(ticketId, data)`: Validate `content`, check if user has access to this ticket (Admin/Tech or they created it).

- [ ] **Step 2: Write Update Action**
- `updateTicket(id, data)`: Update status/priority/assignee.
  - If status becomes `RESOLVED`, set `resolvedAt = new Date()`.
  - If status becomes `CLOSED`, set `closedAt = new Date()`.
  - Must verify permissions: Users can only close their own tickets. Admin/Tech can update any fields.

- [ ] **Step 3: Commit**

```bash

git commit -m "feat: add ticket server actions"
```
